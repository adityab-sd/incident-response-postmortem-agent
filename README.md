# Incident Response & Root Cause Post-Mortem Agent

> A production-grade, multi-agent DevOps triage pod that handles active application alerts from Slack, PagerDuty, and Prometheus Alertmanager, investigates telemetry in parallel, ranks root-cause hypotheses with cited evidence, proposes read-only remediations behind a human approval gate, and generates blameless post-mortems.

---

## Architecture Highlights

- **Tiered Multi-Agent Design (`config/models.yaml`):**
  - **`supervisor` tier:** Groq `llama-3.1-8b-instant` (131k context) with automatic fallback to Gemini `gemini-3.5-flash-lite` (1M context) for low-latency alert intake, routing, and step/token budget enforcement.
  - **`core` tier:** Groq `llama-3.3-70b-versatile` (131k context) with fallback to Gemini `gemini-3.8-flash` (1M context) for log error clustering, metric anomaly detection, deploy correlation, topology traversal, runbook synthesis, hypothesis ranking, remediation proposals, timeline building, and blameless post-mortem writing.
  - **`long_context` tier:** Google Gemini `gemini-3.8-flash` (1M token context window), dynamically routed **only** when a log/telemetry bundle exceeds `long_context_token_threshold` (`24,000` tokens).
- **11 Typed Sub-Agent Tools (`src/incident_agent/subagents/`):**
  - `triage_intake`, `log_analyst`, `metrics_analyst`, `change_correlator`, `topology_mapper`, `runbook_retriever`, `hypothesis_ranker`, `remediation_proposer`, `timeline_builder`, `postmortem_writer`, `diagram_generator`.
- **Defense-in-Depth Safety Controls (`src/incident_agent/safety/`):**
  - **Read-Only by Default & Mandatory Human Action Gate:** Sub-agents can only generate `RemediationProposal` objects (`proposal_only=True`). State-changing actions require a recorded human `ApprovalRecord` in `ActionGate.execute_approved_action()`.
  - **PII & Secret Redaction (`RedactionFilter`):** Scrubs emails, Bearer tokens, JWTs, AWS keys, API keys, database URI credentials, private keys, and configurable IPv4 addresses before any text is persisted or sent to an LLM.
  - **Prompt-Injection Defense (`InjectionFilter`):** Neutralizes instruction-hijacking directives embedded in logs/alerts and isolates untrusted telemetry in `<untrusted_telemetry>` blocks.
  - **Hard Step & Token Budgets (`BudgetEnforcer`):** Caps investigation rounds (`3`), tool calls (`25`), and total tokens (`100,000`) per incident, reporting partial findings gracefully if a cap is hit.
- **Stateful Persistence & Crash Recovery (`src/incident_agent/persistence/`):**
  - LangGraph state machine (`IncidentSupervisor`) checkpoints after every node (`intake`, `investigate`, `rank_hypotheses`, `triaged`, `resolved`) into `SQLiteIncidentStore` (behind the `IncidentStore` protocol so PostgreSQL can replace it in production).

## Quickstart & Local Setup (Under 5 Minutes)

### 1. Create a Virtual Environment & Install Dependencies
```powershell
uv venv .venv
uv pip install -e ".[dev]"
```
*(Or with standard `pip`: `python -m venv .venv && .venv\Scripts\pip install -e ".[dev]"`)*

### 2. Configure Environment Variables
Copy `.env.example` to `.env`:
```powershell
Copy-Item .env.example .env
```

| Environment Variable | Required | Description |
|---|---|---|
| `GROQ_API_KEY` | Optional (Live LLM) | Groq Cloud API key for `supervisor` (`llama-3.1-8b-instant`) and `core` (`llama-3.3-70b-versatile`) tiers |
| `GEMINI_API_KEY` | Optional (Live LLM) | Google Gemini API key for fallback and `long_context` (`gemini-3.8-flash`) tier |
| `USE_MOCK_LLM` | Default: `auto` | Set to `true` for deterministic offline fixture execution, or `auto` to use live keys when present |
| `SLACK_BOT_TOKEN` | Optional | Slack Bot OAuth token (`xoxb-...`) |
| `SLACK_DEFAULT_CHANNEL` | Default: `C01INCIDENTS` | Default Slack channel for incident threads |
| `PAGERDUTY_API_KEY` | Optional | PagerDuty REST API token |
| `INCIDENT_DB_PATH` | Default: `./data/incidents.db` | SQLite persistence file path (or `:memory:`) |
| `CONFIG_MODELS_PATH` | Default: `./config/models.yaml` | Path to model tier configuration |
| `CONFIG_THRESHOLDS_PATH` | Default: `./config/thresholds.yaml` | Path to investigation budgets and safety configuration |

## Running the Incident Simulator

Run all 5 synthetic scenarios (`bad_deploy`, `dependency_timeout`, `db_pool_exhaustion`, `config_flag_misfire`, `traffic_spike`) end-to-end and generate `docs/postmortem-example.md`:

```powershell
.venv\Scripts\python.exe scripts/simulate_incident.py --write-example-postmortem docs/postmortem-example.md
```

Run a single scenario:
```powershell
.venv\Scripts\python.exe scripts/simulate_incident.py --scenario config_flag_misfire
```

## How to Add a New Sub-Agent Tool

1. **Define Input & Output Schemas (`src/incident_agent/schemas.py`):**
   Add `MyNewSubagentInput(BaseModel)` and `MyNewSubagentOutput(BaseModel)` with `model_config = ConfigDict(extra="forbid")`.
2. **Add Budget Entry (`config/models.yaml`):**
   Add your tool under `subagent_budgets:` with `role` (`supervisor`, `core`, or `long_context`), `timeout_seconds`, and `max_tokens`.
3. **Create the Sub-Agent Module (`src/incident_agent/subagents/my_new_subagent.py`):**
   - Implement `run_my_new_subagent(inp: MyNewSubagentInput, ctx: SubagentRuntimeContext) -> MyNewSubagentOutput`.
   - Use `ctx.sanitize_and_redact()` on any untrusted text and `ctx.record_evidence()` to register evidence IDs.
   - Call `get_chat_model(ModelRole.CORE, subagent_name="my_new_subagent", tracer=ctx.tracer, config=ctx.config)`.
   - Expose `build_my_new_subagent_tool(ctx) -> StructuredTool` using `StructuredTool.from_function`.
4. **Register the Tool (`src/incident_agent/subagents/__init__.py` & `supervisor/graph.py`):**
   Include `build_my_new_subagent_tool(ctx)` in `build_all_subagent_tools(ctx)` and wire it into the appropriate node in `IncidentSupervisor`.
5. **Add Unit & Integration Tests (`tests/unit/` and `tests/integration/`):**
   Verify schema validation, graceful degradation on adapter error, and budget accounting.
